MILP가 지연되면 처리 가능한 작은 enumeration으로 core를 보여주고 입력 크기 제한을 명시한다. 미완성 기능을 작동한다고 발표하지 않는다.

### V1 acceptance

- 실제 가격·UTC·간격·단위·출처가 표시된다.
- 모든 작업을 완료하고 release/deadline/연속가동/상한을 독립 검사한다.
- 동일 조건으로 Greedy와 공동 일정을 비교한다.
- 알려진 €2,323.84 / €2,198.80 사례와 release 변경을 실제 데이터로 재현한다.
- 불가능 조건·입력 오류·solver timeout을 구분한다.
- 출력은 Wholesale Cost Proxy이며 기업 총 전기요금·검증된 절감률이 아니다.
- 팀원의 깨끗한 환경에서 실행 방법을 검증한 후 Quick Start를 업데이트한다.

## V2 — Forecast + Optimization

가격 공개 전에 작업 확정이 필요하거나 미공개 기간을 계획해야 하는 실제 의사결정이 확인될 때 착수한다.

오성민: available_at·issued_at·시간순 분할 → 단순 forecast baseline → ML 한 개 → 같은 optimizer의 실제가격 비용/regret 평가. 정병주: 데이터·모델 연결 review. 남하원: 최적화 정보 계약 확인.

MAE만 좋아졌다고 Business Value를 주장하지 않는다. 미래 실제 부하·발전·기상 사용 금지. 필요성이 없다면 known-price core를 유지한다.

## V3 — Scenario / CVaR / Battery

1. 과거 rolling 잔차의 하루 경로로 시나리오 후보 생성·보정.
2. 같은 시나리오의 기대비용·CVaR 일정 비교. 모든 미래에 동일한 최초 일정.
3. 평균 비용과 tail cost trade-off 검증.
4. 배터리는 별도 확장: 용량·효율·MW·초기/종료 SOC·동시 충방전 금지·수출 조건 명시.

충분한 데이터와 시간이 있을 때 진행한다. V3 완료·실제 위험 감소는 현재 확인된 사실이 아니다.
